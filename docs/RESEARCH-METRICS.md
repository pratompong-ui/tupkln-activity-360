# Research Metrics สำหรับ คศ.4 และการต่อยอด คศ.5

เป้าหมายคือเก็บข้อมูลระยะยาวเพื่อแสดงพัฒนาการของกระบวนการทำงานและผลลัพธ์ โดยไม่ลดคุณค่าของงานครูเหลือเพียงจำนวนรายการ ข้อมูลต้องมีนิยามคงที่ ตรวจสอบย้อนกลับได้ และใช้ประกอบหลักฐานเชิงคุณภาพ

## ชุดตัวชี้วัดที่ควรเก็บ

| มิติ | ข้อมูลดิบที่ควรเก็บ | ตัวชี้วัดตัวอย่าง |
|---|---|---|
| ระยะเวลาการเตรียมงาน | วันที่สร้าง, วันที่มอบหมาย, วันที่เริ่มทำ, due date, วันที่เสร็จ | lead time, cycle time, สัดส่วนงานเสร็จก่อนกำหนด |
| งานเลยกำหนด | due date, completed date, สถานะ, เหตุผลที่ล่าช้า | overdue rate, จำนวนวันล่าช้าเฉลี่ย/มัธยฐาน, backlog aging |
| การสรุปผล | วันสิ้นสุดกิจกรรม, วันที่ปิดงาน, ความครบถ้วนของผล/เอกสาร | completion rate, เวลาจากจบกิจกรรมถึงสรุปผล |
| การมีส่วนร่วม | กลุ่มเป้าหมาย, จำนวนคาดหมาย, จำนวนเข้าร่วม, บทบาท/กลุ่ม | participation rate, coverage, การมีส่วนร่วมซ้ำ |
| ภาระงาน | กลุ่มรับผิดชอบ, ผู้รับผิดชอบ, จำนวนงาน, effort estimate | workload ต่อกลุ่ม/ช่วงเวลา, งานซ้อน, distribution balance |
| ผลลัพธ์ | เป้าหมาย, output, outcome indicator, baseline/target/actual | อัตราบรรลุเป้าหมาย, แนวโน้มผลลัพธ์, evidence coverage |
| คุณภาพกระบวนการ | revision count, blocker, risk, feedback, corrective action | rework rate, blocker resolution time, lesson adoption |

## ฟิลด์เชิงเหตุการณ์ที่ควรออกแบบในอนาคต

อย่าเขียนทับเฉพาะสถานะล่าสุด ควรมี event/audit record ที่ประกอบด้วย:

- `event_id`, `event_type`, `occurred_at`, `recorded_at`
- `activity_id`, `task_id` หรือ `document_id`
- shared `actor_id`, `unit_id`, `academic_term_id`
- previous/new status, due date revision และ reason code
- source module และ schema/event version

งาน V2 นี้ยัง **ไม่เพิ่ม schema** รายการข้างต้นเป็นข้อเสนอสำหรับการออกแบบและอนุมัติในระยะถัดไปเท่านั้น

## นิยามตัวชี้วัดหลัก

- **Preparation lead time:** วันเริ่มกิจกรรมลบวันที่สร้าง/อนุมัติงาน
- **Task cycle time:** วันที่ทำเสร็จลบวันที่เริ่มทำหรือวันที่มอบหมาย
- **Overdue rate:** งานที่เสร็จหลังกำหนดหรือยังไม่เสร็จเมื่อพ้นกำหนด หารด้วยงานที่มีกำหนดทั้งหมด
- **Summary turnaround:** วันที่สรุปผลลบวันสิ้นสุดกิจกรรม
- **Activity closure rate:** กิจกรรมที่ปิดพร้อมหลักฐานครบ หารด้วยกิจกรรมที่สิ้นสุดแล้ว
- **Participation rate:** จำนวนเข้าร่วมจริงหารด้วยจำนวนกลุ่มเป้าหมายที่คาดหมาย โดยต้องระบุวิธีนับที่สม่ำเสมอ
- **Workload balance:** เปรียบเทียบจำนวน/effort ของงานระหว่างกลุ่มในช่วงเวลาเดียวกัน ไม่ใช้จำนวนงานอย่างเดียว
- **Outcome attainment:** actual เทียบ target พร้อมแนบหลักฐานและบริบท

## ระดับการสรุปผล

ควรรายงานอย่างน้อย 4 ระดับ:

1. รายกิจกรรม — timeline, ผู้รับผิดชอบ, participation, output/outcome, บทเรียน
2. รายกลุ่มงาน — ภาระงาน งานล่าช้า อัตราปิดงาน และแนวโน้ม
3. รายภาคเรียน/ปีการศึกษา — เปรียบเทียบช่วงเวลาและเป้าหมาย
4. ระดับโรงเรียน — aggregate สำหรับผู้บริหารโดยจำกัดข้อมูลส่วนบุคคล

## คุณภาพข้อมูลและจริยธรรม

- ระบุ data owner, ผู้บันทึก, แหล่งหลักฐาน และเวลาที่แก้ไขล่าสุด
- ใช้ controlled vocabulary สำหรับสถานะ เหตุผลล่าช้า ประเภทกิจกรรม และ outcome
- เก็บทั้ง denominator และ numerator เพื่อไม่ให้เปอร์เซ็นต์คลุมเครือ
- แยก “ไม่มีข้อมูล” ออกจากค่า 0
- ไม่ใช้ตัวชี้วัดเดี่ยวตัดสินผลการปฏิบัติงาน และต้องเปิดพื้นที่ให้บันทึกบริบทเชิงคุณภาพ
- จำกัดข้อมูลรายบุคคลตามบทบาท กำหนด retention period และทำ anonymization เมื่อนำไปวิจัย
- ทำ data-quality review เป็นรอบ และบันทึกนิยาม metric/version ทุกครั้งที่เปลี่ยน

## หลักฐานสำหรับ คศ.4/คศ.5

ระบบควร export ชุดหลักฐานที่เชื่อมโยงกันได้: แผนงาน → การดำเนินงาน → หลักฐาน → ผลลัพธ์ → การสะท้อนผล → การปรับปรุงรอบถัดไป พร้อม timestamp และผู้รับรอง โดยใช้ข้อมูลเชิงปริมาณสนับสนุน narrative ไม่ใช่แทนที่ narrative
